# 실험 설계

## 질문

음성 대화에서 사용자의 실제 의도를 맞히는 정확도를 올리려 할 때, 어떤 방법이 지연을 얼마나 늘리고 정확도를 얼마나 올리는가?

## 질의셋

`data/queries.json` 의 30개 문항. 각 문항은 다음을 가집니다.

| 필드 | 뜻 |
|---|---|
| `utterance` | 음성 인식 결과처럼 쓴 사용자 발화. 문장부호 없음, 군말("어", "음") 포함, 반말·존댓말 혼용 |
| `state` | 기기 상태(장소, 온도, 재생 중인 곡, 예약 등). 시스템 프롬프트에 "현재 상태"로 들어감 |
| `context` | 직전 대화 턴 (없을 수 있음) |
| `category` | 화용 현상 분류 13종 ([화용론 개요](pragmatics.md#이-리포의-분류표)) |
| `gold_intent` | 정답 의도 |
| `must` / `must_not` | 응답이 반드시 해야 할 것 / 하면 안 되는 것 |
| `clarify_ok` | 올바른 행동을 콕 집어 확인하는 질문도 정답으로 볼지 |

질의셋은 모델 호출 전에 고정했습니다. 실험 결과를 보고 문항이나 정답을 고치지 않습니다. 고친다면 버전을 올리고 전체를 다시 돌립니다.

## 조건

| 조건 | 내용 | 스트리밍 | 지연에 들어가는 것 |
|---|---|---|---|
| A0 effort 하향 (Mercury 3 만) | A1 에서 reasoning_effort 만 instant 로 낮춤 | 예 | 응답의 첫 텍스트 |
| A1 기본 | 각 모델의 음성용 기본 설정 | 예 | 응답의 첫 텍스트 |
| A2 effort 상향 | A1 에서 추론 강도만 한 단계 올림 | 예 | 추론 + 응답의 첫 텍스트 |
| A3 화용 서브에이전트 | 같은 모델이 A2 강도로 화용 분석 JSON 생성 → A1 설정 응답 모델이 분석을 받아 응답 | 분석: 아니오 / 응답: 예 | 분석 전체 + 응답의 첫 텍스트 |
| A4 화용 점검표 (요청 외 추가) | 별도 호출 없이 A1 시스템 프롬프트에 화용 점검표만 추가 | 예 | 응답의 첫 텍스트 |
| X 교차 A3 | 분석 모델과 응답 모델을 다른 제공자로 조합 (mercury→luna, luna→mercury) | 분석: 아니오 / 응답: 예 | 분석 전체 + 응답의 첫 텍스트 |

모델별 정확한 파라미터는 [모델별 설정과 출처](model-settings.md)에 있습니다.

A4 는 요청 범위 밖이지만, A3 의 정확도 향상이 "분석을 따로 하는 구조" 덕분인지 "화용 지식을 주입한 것" 덕분인지 가르기 위해 넣었습니다. A4 가 A3 와 비슷한 정확도를 내면 서브에이전트의 추가 지연은 필요 없다는 뜻입니다.

## 지표

- **의도 파악 정확도**: 채점 점수(0/1/2)의 평균을 2로 나눈 값. 문항별로 반복 평균을 낸 뒤 30문항 평균.
- **엄격 정확도**: 2점 비율.
- **95% 신뢰구간**: 문항 단위 부트스트랩 2000회.
- **첫 발화 지연** (`e2e_first_ms`): 요청을 보낸 시점부터 비어 있지 않은 첫 보이는 텍스트가 도착한 시점까지. 추론 토큰과 thinking 블록은 보이는 텍스트가 아니므로 이 시간 안에 들어갑니다. A3·X 는 분석 호출 전체 시간을 더합니다.
- **첫 문장 지연** (`e2e_sentence_ms`): 누적 텍스트에 처음으로 문장 끝 부호(. ! ? …)가 나온 시점. 음성 합성을 문장 단위로 시작하는 파이프라인의 지연에 가깝습니다.
- **분석 정확도** (A3·X): 분석 JSON 의 `intended_meaning`·`action` 이 정답 의도와 맞는지 별도 채점. 응답이 틀렸을 때 분석이 틀렸는지, 분석은 맞았는데 응답 모델이 못 따랐는지 가릅니다.
- **의도 이해율** (실행 후 추가한 보조 지표): 2점이거나, 1점이면서 채점 플래그가 "확인 질문함 + 문자적 해석·틀린 대상·과잉 행동 없음"인 비율. 의도는 맞히고 실행 전에 확인만 한 응답을 정답으로 봅니다. 실행 후 채점 결과를 보고 추가한 지표이므로 주 지표(의도 정확도)를 대체하지 않습니다.
- **A1 대비 변화**: 같은 문항끼리 짝지어(쌍체) 각 조건과 같은 응답 모델의 A1 의 차이를 구하고, 문항 단위 부트스트랩(2000회)으로 95% 신뢰구간을 냅니다. 모델 합산은 문항마다 모델별 차이를 평균한 뒤 문항 단위로 재표집합니다. Gemini 3.5 Flash-Lite A2(LOW)는 270회 모두 추론 토큰 0 이라 effort 가 실제로 오르지 않았으므로 effort 상향 합산에서 뺍니다 (`POOL_EXCLUDE`).
- **모델 간 비교**: 각 모델의 기본 설정을 Mercury 3 A1(공식 음성 가이드 설정)과 같은 방식으로 짝지어 비교합니다.
- **1,000턴당 비용**: 기록된 토큰 사용량 × 공식 가격(`vib/report.py` 의 `PRICES`). A3·X 는 분석 호출을 포함합니다. Gemini 는 추론 토큰이 `total - prompt` 로만 드러나 그 값을 출력으로 계산합니다.
- **평균 글자 수**, **마크다운 비율**: 음성용 출력 형식을 지켰는지 보조 지표. 마크다운 비율은 전 조건 0% 였습니다.
- 부트스트랩은 고정 시드와 정렬된 문항 순서를 써서, 같은 로그에서는 항상 같은 값이 나옵니다.

## 측정 절차

- 각 (조건, 문항)을 3회 반복합니다.
- 제공자마다 워밍업 호출 1회 후 측정을 시작합니다 (연결 수립 비용 제외).
- 같은 제공자 호출은 순차로, 다른 제공자끼리는 병렬 스레드로 돌립니다. 교차 조건(X)의 분석 호출은 응답 모델 쪽 스레드에서 나가므로 분석 제공자의 스레드와 동시에 호출될 수 있습니다.
- 문항마다 조건 순서를 돌려, 특정 조건이 특정 시간대에만 몰리지 않게 합니다.
- 오류가 나면 2초 뒤 한 번 재시도하고, 그래도 실패하면 오류로 기록합니다. 오류 행은 정확도·지연 계산에서 빠지고 표의 "오류" 열에 개수가 남습니다.

## 채점

- 채점 모델: `claude-opus-5-5` (effort low, JSON 스키마 강제 출력). 실험 대상이 아닌 상위 모델을 씁니다.
- 블라인드: 채점 모델은 조건 이름, 모델 이름, 지연을 보지 않습니다. 문항(상태, 맥락, 발화, 정답, must/must_not)과 응답 텍스트만 봅니다.
- 루브릭: 2 = 정답 의도 반영, must 전부 충족, must_not 위반 없음 / 1 = 방향은 맞지만 불완전하거나 불필요하게 되물음 / 0 = 오해, 문자적 의미로만 답함, 틀린 대상·값, 하지 말아야 할 행동.
- 채점 모델이 refusal 을 내면 다른 모델로 대체하지 않고 채점 오류로 남깁니다 (채점자가 섞이지 않도록).
- 채점 결과 일부를 사람이 직접 검수하고 그 결과를 README 에 적습니다.
- 실제 진행: 채점 도중 Anthropic 계정 사용 한도에 걸려 세 번에 나눠 채점했습니다. 같은 채점 모델·프롬프트·설정이며, 한도 오류로 실패한 행은 버리고 다시 채점했습니다. 한도 같은 복구 불가 오류를 만나면 채점기가 즉시 멈추도록 고쳤습니다.

## 한계

- **문항 수가 작습니다.** 30문항, 일부 분류는 1~2문항입니다. 분류별 수치는 경향으로만 읽어야 합니다.
- **정답은 한 사람이 작성했습니다.** 화용 해석에는 정답이 하나가 아닌 경우가 있어 `clarify_ok` 와 1점 구간으로 완충했지만, 작성자의 해석이 들어가 있습니다.
- **일부 문항의 정답 기준이 확인 질문에 지나치게 엄격합니다.** REP-01(치과 이름을 묻는 것), HON-01(문자로 보낼지 확인하는 것)처럼 빠진 정보를 묻거나 되돌리기 어려운 행동 전에 확인하는 응답이 1점이 됐습니다. QFR-02 는 "갈 수 있나"에 도착 가능 여부로 답한 응답을 길안내 제안이 없다는 이유로 0점 처리해, 함축 해석이 갈리는 문항입니다. 결과를 본 뒤 정답을 고치지 않았고, 대신 의도 이해율을 함께 보고합니다. 다음 버전에서는 "되돌리기 어려운 행동은 확인 허용"을 정답 기준에 명시하고, 함축이 논쟁적인 문항은 복수 정답으로 바꿔야 합니다.
- **비교가 많습니다.** 20개가 넘는 비교를 각각 95% 신뢰구간으로 보고하므로, 우연히 0 을 벗어나는 비교가 한두 개 나올 수 있습니다. 실제로 사실상 같은 설정(Gemini 3.5 Flash-Lite A1 과 A2, 둘 다 추론 토큰 0)의 차이가 −3.9%p (−8.3~0.0)로 경계에 걸렸습니다.
- **천장 효과.** 간접 요청, 전제, 음성 인식 오류는 거의 모든 조건이 100% 여서 방법 간 차이를 가르지 못합니다.
- **A3·A4 프롬프트와 질의셋이 같은 분류 체계를 씁니다.** 분석 프롬프트와 점검표가 질의셋의 화용 현상 이름을 직접 다루므로, A3·A4 의 향상은 처음 보는 발화에서보다 낙관적으로 나올 수 있습니다. 예시 문장은 질의셋과 겹치지 않게 썼습니다. 일반화하려면 별도 검증 세트가 필요합니다.
- **채점 모델의 편향.** Anthropic 채점 모델이 같은 회사의 Haiku 응답을 후하게 볼 가능성을 배제할 수 없습니다.
- **텍스트 전용입니다.** 실제 음성 인식과 음성 합성은 없습니다. ASR 결과처럼 쓴 텍스트를 넣고, 첫 텍스트 시점을 음성 합성 시작 시점의 대리 지표로 씁니다.
- **도구 호출이 없습니다.** 비서가 "켰어요"라고 말하면 실행한 것으로 봅니다. 실제 도구 호출을 넣으면 지연과 정확도가 달라질 수 있습니다.
- **지연은 측정한 장소와 시간의 네트워크를 포함합니다.** 한국에서 각 제공자의 공개 API 로 호출한 값이며, 제공자 부하와 지역에 따라 달라집니다. 절댓값보다 같은 조건에서의 상대 비교로 읽어야 합니다.
- **A3 는 순차 실행입니다.** 분석이 끝나야 응답을 시작합니다. 실제 서비스에서는 짧은 맞장구를 먼저 말하는 동안 분석하거나, 분석과 응답을 추측 실행으로 겹쳐 지연을 숨길 수 있습니다. 이 리포의 A3 지연은 그런 최적화가 없는 상한입니다.
