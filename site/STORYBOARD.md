# 결과 페이지 스토리보드

대상: 비개발자, 디자이너, PO, CTO. 한 번 훑어보는 데 4분 안팎, 장면마다 핵심 문장 하나.
대표 예시 하나를 끝까지 들고 간다: SAR-02 "하 이거 들으면 잠 참 잘 오겠다" (새벽 1시, 수면 음악을 부탁했는데 헤비메탈이 나오는 중).

## 장면

| 장면 | 핵심 문장 | 화면 | 움직임 |
|---|---|---|---|
| 1. 문제 | 빠른 음성 비서는 말을 글자 그대로 받아들인다 | 대화 무대: Codex 로 그린 새벽 1시 침실(사람 자세 4장, 스마트 스피커, 탁상시계), 말풍선, 생각, 기록 카드 | 같은 대화를 두 번: 글자 그대로 답하는 비서(빨간 테두리, 이마를 짚는 사람) → 생각으로 말뜻을 읽는 경우(초록 테두리, 안도하는 사람). 스피커 빛 고리가 음악(주황, 168 BPM 박자)·생각(초록)·말함(흰색)을 보여 준다 |
| 2. 목표 | 정확한 모델은 느리다. 빠르면서 정확한 칸을 노린다 | 지연(가로) 대 정확도(세로) 지도, 기본 모델 6개 | 점이 하나씩 떨어지고, 왼쪽 위 '목표 칸'이 서서히 밝아진다 |
| 3. 언제 일하나 | 같은 아이디어도 언제 계산하느냐에 따라 속도가 갈린다 | 한 번의 대화 턴 시간축 (Remotion): 말하기 전 / 사용자가 말함 / 첫 소리까지 기다림. 그림에서 잘라 낸 얼굴·스피커·도우미 | 줄마다 사용자가 말하고(파형), 기다림 막대가 첫 소리 중앙값만큼 자란 뒤 스피커가 말한다. 미리 짐작은 왼쪽 칸에서 상위 모델이 카드를 넘기고, 분석 서브에이전트는 막대 위에서 일하는 동안 사용자가 기다린다 |
| 4. 시도한 방법 | 6개 묶음, 18가지를 시험했다 | 위 방법 목록 + 아래 전체 폭 대화 무대 (여행 문항은 거실 그림) | 방법을 누르면 그 방법이 하는 일을 무대로 보여 준다: 생각(해석·점검표·짐작), 도우미 그림(상위 모델·분석 에이전트·게이트), 기록 카드, 기다림 초시계, 온도 다이얼. 비서의 말은 실제 응답 |
| 5. 결과 | 방법마다 점이 어디로 움직였나 | 장(1~3차 / 후보 선별 / 싼 추정 / 여행 개인화 / 온도)별 지연·정확도 지도 | 기준점에서 결과 위치로 점이 이동하고, 신뢰구간 막대가 뒤따라 나타난다 |
| 6. 문제점 | 좋아 보였던 방법도 대가가 있었다 | 방법별 문제 카드: 그 방법 무대의 끝 화면 썸네일 + 숫자 하나 + 한 줄 | 카드가 시차를 두고 올라온다. 설명 글은 두 줄까지만 보이고 마우스를 올리면 펼쳐진다. 누르면 시도한 방법 장면에서 그 무대를 재생한다 |
| 7. 가장 나은 방법 | 말하기 전에 상황을 해석해 두고, 빠른 모델이 바로 답한다 | 우승 방법 강조 + 대화 무대로 전/후 예시 2개 | 지도에서 우승 점만 남고 나머지는 흐려진다. 무대에서 짐작 없이 답한 경우 → 상위 모델이 미리 만든 짐작 카드가 날아온 뒤 답한 경우 |
| 8. 다음 | 남은 질문과 방법을 더하는 방법 | 남은 질문 목록, 데이터 파일 구조 | 정적 |

## 무대 정보

- 대화 무대마다 아래 정보 띠에 계산 시점, 응답 모델(설정), 도우미 모델, 방법이 하는 일, 이 조건의 정확도와 첫 소리(기준 → 결과), 문항 수를 적는다. 값은 `methods.json` 의 `models`·`metric`·`base` 와 `metrics.json` 에서 온다.
- 스피커 아래 이름표는 그 막에서 답하는 모델이다. 도우미 그림의 이름표도 모델 이름이다(Gemini 3.8 Flash, Mercury 3 high, Jev).
- 비서가 기다리는 동안(분석·게이트·생각 더 하기)은 비서 자리에 점 3개가 차례로 깜빡이고, 기다린 시간을 센다. 다 기다린 뒤에는 이름표에 그만큼 늦게 말했다고 붙는다.
- 자리 폭이 640px 보다 좁으면(휴대폰) 세로 배치로 바꾼다: 위에 그림, 아래에 생각 → 사람 말 → 비서 말 → 정보 띠.

## 속도

- 문장 노출: 한 글자당 약 0.12초(초당 8음절) + 정착 1.5초. 텍스트를 다 읽기 전에 다음 움직임이 시작되지 않게 한다.
- 등장 움직임 700ms, 시차 120ms, 점 이동 1,200ms(눈으로 따라갈 수 있게), 감속 곡선(easeOutCubic).
- 기본은 한 화면 발표다. 스크롤 없이 장면이 제자리에서 바뀌고, 장면의 움직임이 끝나면 설명 글 길이만큼(2.5~7초, 속도 설정을 따름) 머문 뒤 다음 장면으로 넘어간다. 시도한 방법 장면은 계산 시점마다 하나씩(화용 점검표 · 분석 서브에이전트 · 상위 모델 미리 짐작), 결과 장면은 다섯 장을 차례로, 가장 나은 방법 장면은 차트 다음 같은 칸에서 대화 무대로 바뀐다.
- 아래 막대: 이전 · 장면 점 · 장면 이름 · 자동 넘김 켬/끔 · 다시 보기 · 다음. 키보드 →·PageDown·Space 다음, ←·PageUp 이전. 휴대폰은 옆으로 쓸어 넘긴다. 무엇이든 누르면 자동 넘김이 멈춘다.
- 무대와 차트는 남은 칸을 채우고, 무대는 넓은·세로 배치 중 더 크게 보이는 쪽을 고른다. 휴대폰 폭에서는 설명을 제목만 남기고 방법 목록은 선택 상자가 된다.
- `?scroll` 을 붙이면 예전처럼 아래로 이어진 긴 페이지가 된다(장면 윗부분이 화면 위쪽 60% 안에 들어오면 시작). `#장면` 이나 `?scene=장면` 으로 시작 장면을 고른다.
- 움직임 줄이기 설정(prefers-reduced-motion)이면 최종 상태를 바로 보여 준다.

## 차트 장면 시안

결과 장면(5)은 형태 판단이 어려워 시안 3개를 둔다. 본 페이지는 A 를 쓴다.

- A. 지도: 지연·정확도 평면에서 점이 이동 (`index.html`)
- B. 전후 막대: 방법마다 정확도 변화 막대와 지연 변화 막대를 나란히 키움 (`drafts/chart-b.html`)
- C. 입체: 지연·정확도·비용 3축 공간에서 기둥이 솟고 시점이 천천히 돈다, three.js (`drafts/chart-c.html`)

## 방법 더하기

1. `vib/site_data.py` 의 `METRICS` 에 결과 파일 경로를 더하고 `python -m vib.site_data` 로 `site/data/metrics.json` 을 다시 만든다.
2. `site/data/methods.json` 에 카드(묶음, 계산 시점, 역할, 예시 프롬프트·출력, 문제점, 지표 키)를, `site/data/stages.json` 에 무대 대본(say, think, cards, helper, clock, dial 단계)을 더한다. 비서의 말과 짐작은 실제 결과에서 가져온다. 무대는 `video/` 의 Remotion 코드가 그리며, 대본만 더할 때는 다시 묶을 필요가 없다 (`video/README.md`).
3. 결과 장면에 보이려면 `site/data/chapters.json` 의 해당 장에 점을 더한다. 새 장도 같은 형식으로 더한다.
